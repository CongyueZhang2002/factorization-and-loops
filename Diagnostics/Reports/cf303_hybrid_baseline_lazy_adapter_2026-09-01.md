# CF303 deferred-baseline lazy adapter — 2026-09-01

## Result

The accepted deferred baseline circuit now has a scratch-only adapter to the
existing one-incoming-edge GPL/eMPL weighted-Chen interface.  It does not build
characteristic-zero `2x43` matrices of baseline `H` or recurrence-generated
cross-`K`.  No package source is changed.

The adapter is
`Diagnostics/Scripts/cf303_hybrid_baseline_lazy_circuit_adapter.wl`.  Its
compact exact-leaf/support contract is
`cf303_hybrid_baseline_lazy_adapter_manifest.json`.  The pure-Python smoke
result is `cf303_hybrid_baseline_lazy_adapter_validation.json`.

## Exact dataflow

1. Load the accepted 43-master source operator
   `cf303_hybrid_elliptic_operator_15_17_21.wl` and reuse its canonical Chen
   residues, 287 source boundary columns, letters, and composite definitions.
2. Pass the accepted 76-entry base transfer to
   `cf303BuildLazyFinalEllipticOperator`.  This supplies ordinary incoming
   `G` leaves and the two-target diagonal operator.  Six target boundary
   constants are appended, giving boundary dimension 293.
3. Attach the twelve accepted block 2/11/14/18 exception remainders as exact
   provider-backed composite `K` leaves.  There are 12 coordinates times eight
   Laurent orders, hence 96 lazy labels.  Their large exact expressions remain
   in the four accepted census providers.
4. Represent the complete merged gauge by
   `CF303HybridBaselineH[n,targetMaster,sourceMaster,channel,p,u]`.  The head
   addresses the accepted sealed recurrence, including every exception
   primitive, baseline feed-down into column 1, and the separately accepted
   block-1 `delta H`.  Both `{1,Y}` channels are explicit, but only 112 inert
   addresses are stored: eight orders, two target rows, seven source columns.
5. Attach each recurrence-generated cross-Hermite remainder as
   `{"CF303HybridBaselineCrossK",n,targetMaster,sourceMaster}`.  Order `-3`
   is structurally zero; orders `-2..4` contain 98 order-coordinate labels.
6. Reuse the existing 32 block-1 rational/elliptic `delta K` labels and point
   resolver.  Block-1 `delta H` is not added a second time: it is already in
   the unified `H` circuit head from step 4.
7. Use the established coefficient routines unchanged:
   `F25=G25+H.L` for canonical word coefficients, followed by the accepted
   physical gauge orders `T25[0..2]` for `I25=T25.F25`.  Root/factor expansion
   is still performed only for a requested physical word.

The accepted incoming `K` leaves are not regenerated by the recurrence.  The
new cross-`K` nodes are additional incoming letters, so neither the base nor
exception remainder terms are lost.

## Support proof used by the adapter

The twelve nonzero primitive leaves occupy source masters
`{2,12,21,22,29,30}` in both target rows.  A coordinate-only parse of the
accepted source `S` records gives

```text
2  -> {1,2}
12 -> {1,12}
21 -> {1,12,21,22}
22 -> {1,12,21,22}
29 -> {1,12,29,30}
30 -> {1,12,29,30}
1  -> {1}
```

Therefore the exact graph closure is
`{1,2,12,21,22,29,30}`.  Target `D` only mixes the two target rows and cannot
change a source column.  This proves the seven-column/14-coordinate support
independently of finite-field values.  In particular, column 1 is retained as
baseline feed-down plus block-1 correction; it is not replaced by block 1.

## Evaluator ABI

The accepted evaluator has one optional output mode:

```bash
python3 Diagnostics/Scripts/cf303_hybrid_baseline_modular_circuit.py \
  --p NUM/DEN --adapter-output OUTPUT.json
```

With no `--output`, this mode does not overwrite the accepted summary image.
The point payload has status `CF303HybridBaselineLazyAdapterPointV1` and
contains:

- 112 merged-`H` records for orders `-3..4`;
- 98 cross-`K` records for orders `-2..4`;
- target/source master labels and pair channels for every record;
- rational functions over `F_q2=F_q[omega]/(omega^2-2)`, with ascending
  numerator/denominator coefficient lists.

Both real payloads were emitted successfully after the structural smoke.
The `p=3` payload took 36.66 s and 107,144 KiB peak RSS; the nonsplit
`p=239/47` payload took 40.54 s and 121,064 KiB peak RSS.  Each contains
exactly 112 merged-`H` and 98 cross-`K` records.

`cf303HybridBaselineCircuitPointRules` resolves an `H` address to the explicit
field head `CF303Fq2[a,b,q]`.  The cross-`K` resolver converts rational-function
records to root-free `GPLFactor` terms (and supports `E4Factor` channels, which
are zero in both accepted images).  It never presents residues modulo `q` as
characteristic-zero rational numbers.

## Acceptance and smoke scope

`cf303_validate_hybrid_baseline_lazy_adapter.py` starts no Wolfram or Maple
kernel.  It parses the exact transfer/path containers, checks the independent
support graph, accepted provider statuses, order-coordinate label counts,
boundary dimensions, Python syntax, Wolfram delimiter balance, and a synthetic
ABI shape.  Arithmetic acceptance comes only from the two previously produced
61-bit images at `p=3` and `p=239/47`:

- 1,376 recurrence and 1,376 basepoint comparisons;
- 4,816 merged-`H` T25 scalar-channel comparisons;
- 1,344 cross-`K` T25 scalar-channel comparisons;
- 49 nonzero cross-`K` vectors per point, with zero elliptic cross reductions.

The smoke status is `CF303HybridBaselineLazyAdapterAcceptedV1`.  This is a
structural adapter acceptance backed by the already accepted circuit images;
it is not a new symbolic identity claim.

## Remaining before paper-ready materialization

The adapter is executable as a lazy operator, but it is intentionally not a
paper expression.  Paper-ready output still requires an on-demand driver that
selects a target epsilon order and boundary word, resolves only the encountered
exception/circuit leaves, performs the standard marked-point expansion, fixes
the published elliptic branch conventions, and exports the surviving
GPL/eMPL words under explicit word/term caps.  If characteristic-zero explicit
circuit coefficients are desired, they must be reconstructed leaf-wise or
word-wise from sufficient images; a dense `2x43` reconstruction is neither
needed nor intended.

The Wolfram adapter was not executed in this pass because the shared kernel
pool was reserved.  Its delimiter/interface smoke passed without a kernel; a
single later scratch build is the remaining runtime integration check.  The
stale 76-entry low-order materialization remains quarantined and is not an
input.
