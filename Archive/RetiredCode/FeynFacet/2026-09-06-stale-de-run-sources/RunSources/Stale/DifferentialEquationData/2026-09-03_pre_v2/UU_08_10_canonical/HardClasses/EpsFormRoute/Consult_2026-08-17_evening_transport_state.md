## Problem 1: word-mass wall in transport (CF299, CF407; also the
## two-root transports)

Both families (dims 22/24, 17 blocks) die at block 8: word count x5-6 per
eps-order (1 -> 12 -> 72 -> 390 -> 2009 words by eps^1; ~10-13k at eps^2).
Measured cause: masters need only eps^2, but the demanded rows of TTotal
(= diag(T_class) . S) carry eps^-3 against most F-columns, so F is honestly
required through 5 relative orders = full weight-4/5 word closure down a
17-block chain. Verified NOT a scheduling bug (demand propagation is
row-restricted and correct); verified NOT removable by per-class scalar
eps-rescaling (relative offsets are gauge-invariant). Families with the
same eps-depth but shallow demanded chains (CF230: 6 blocks; CF384: 20
blocks) succeed.

Codex (parallel assistant) reviewed and proposes the fix we now favor:
exact two-sided projected transport. Build (a) a CERTIFIED boundary map
C(eps) = C0(eps) + B(eps) c(eps) so F = U C0 + U B c (from branch absence,
regularity, known volume integrals, lower-sector inheritance — local
Frobenius mode counts alone do NOT justify discarding columns), (b) the
demanded-row projection L from the actual hard-function master
coefficients, then transport L . TTotal . U . B restricted to the
residue-reachable subspace from B visible to L . TTotal. Caveat Codex
stresses and we accept: a word survives iff R_a1...R_an B != 0, so one
cyclic column can generate the full word set — the reachable-subspace
computation must be done, not assumed. Fallback if still exponential:
shared expression graph (DAG) instead of word enumeration. Additional
decisive probe: common centralizer of the residue matrices; scalars-only
proves no eps-dependent basis normalization can remove the TTotal depth.

Q1: Do you endorse this construction order? Is there community-standard
machinery for the residue-reachability computation (the subalgebra
generated by {R_a} acting on span(B)) or for certified boundary maps B at
this scale that we should reuse rather than build?

## Problem 2: the original-frame check — sampled version and two families
## that genuinely fail it (CF50, CF53)

The symbolic original-frame check (substitute the transported solution
into the original DE, prove the residual zero) cost hours on dim>=24
families; per the user's design ruling it is REMOVED from the standard
driver and replaced by exact rational-point sampling: the per-order
residual dI/dtau - Ahat.I is linear in word symbols with rational-function
coefficients; we evaluate at 3 random rational tau points with every word
and symbolic constant replaced by an independent random rational (fresh
per sample; exact arithmetic; seed and points recorded). The engine's own
symbolic zero test is formal-linear (collect by word, Together on each
coefficient — no shuffle/derivative relations used), so sampling has
IDENTICAL semantics to the symbolic check up to Schwartz-Zippel
probability. One implementation bug (derivative-peeled sub-words missing
from the randomization rules) was found and fixed; non-numeric residual
leftovers are now labeled distinctly from genuine nonzero residuals.

Facts on CF50/CF53 (single-quadratic families, Kallen2 chart):
- Their OLD-driver runs (global deep windows) passed the symbolic check at
  eps^0 before being cancelled mid-check.
- Their NEW-driver runs (per-block windows: block demands from TTotal
  Laurent orders, block lower orders from TTotalInverse) fail the sampled
  check in 48-82 s on BOTH path directions, on both the buggy and the
  fixed check, with pure-rational nonzero residuals (no leftover symbols).
- All exact certificates (recursion, valuation) pass for the same runs.
- Audit across 88 records: 67 have at least one genuinely evaluated True
  order (including new-driver records: CF13 with 40, CF18 with 41), 21
  are vacuous (every order refused as InsufficientOrders by the window
  arithmetic — the original couplings' eps-poles exceed the carried
  series window). So the per-block economy is not globally wrong; the
  failure is family-specific.

Working hypothesis: for CF50/CF53 the per-block lower-order truncation
(blockLowerOrders from TTotalInverse row minima) under-covers low orders
in the map-back I = TTotal.F, producing an I series that is incomplete at
the checked orders — caught only because the sampled check made evaluation
affordable; the certificates do not see it because they certify the
synthetic F-system and the schedule, not original-frame completeness.

Q2: What is the necessary AND sufficient window arithmetic for
I = TTotal(eps).F when TTotal and TTotal^-1 both carry eps-poles — i.e.,
the correct per-block lower and upper orders of F so that I is complete on
a demanded order window? Is the standard resolution to compute windows
from TTotal row-support per demanded row AND TTotalInverse column-support
per block (two-sided), rather than row minima alone?

Q3: Do you accept exact rational-point sampling (words as independent
symbols; formal-linear semantics matching the engine's own zero test) as
the standardized original-frame check, with the symbolic identity retired?
Any known failure mode of treating iterated-integral words as independent
symbols in THIS check (residual identities that vanish only via shuffle or
derivative relations rather than coefficient-wise)?
